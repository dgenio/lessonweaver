# Puppetmaster trace ingestion pattern

Puppetmaster-style orchestrators produce useful lesson evidence: job artifacts,
worker findings, risk decisions, patch artifacts, and human corrections. Map
those artifacts into the lessonweaver trace format, then use the normal
detect -> review -> export loop.

lessonweaver remains a review system, not an automatic training loop. A worker
finding is evidence; a reviewed lesson is a human-approved artifact.

## Artifact mapping

| Puppetmaster artifact | lessonweaver trace mapping |
| --- | --- |
| Job id, objective, repository, run id | Top-level `trace_id`, `task`, and `metadata` |
| Worker assignment or role | Event `metadata.worker`, `metadata.role`, or `source` |
| Worker finding | `evaluation_result` with `status: "failed"` for an actionable issue |
| Risk or decision record | `workflow_step` with `metadata.risk_level` / `metadata.decision` |
| Patch artifact | `tool_result` or `workflow_step` with `metadata.patch_id` / `metadata.files` |
| Human correction or reviewer override | `human_correction` |
| Final accepted outcome | Top-level `outcome` such as `corrected_by_human` |

Keep source-specific fields under `metadata`. The trace format ignores unknown
metadata keys, so an ingestion script can preserve Puppetmaster ids without
making lessonweaver depend on Puppetmaster.

## Example trace

```json
{
  "trace_id": "puppetmaster-job-42",
  "source": "puppetmaster",
  "task": "Coordinate workers to repair a payment-service regression",
  "metadata": {
    "job_id": "job-42",
    "repository": "payments/service",
    "coordinator": "puppetmaster"
  },
  "events": [
    {
      "id": "j1",
      "type": "workflow_step",
      "content": "Assigned worker-a to inspect failing checkout tests.",
      "metadata": {
        "worker": "worker-a",
        "role": "test-investigator"
      }
    },
    {
      "id": "f1",
      "type": "evaluation_result",
      "status": "failed",
      "content": "Patch updated checkout code but did not add a regression test.",
      "metadata": {
        "finding_id": "PM-FINDING-001",
        "severity": "high",
        "risk_level": "high",
        "files": ["src/checkout.py", "tests/test_checkout.py"]
      }
    },
    {
      "id": "p1",
      "type": "tool_result",
      "success": true,
      "content": "Patch artifact generated by worker-b.",
      "metadata": {
        "patch_id": "patch-17",
        "worker": "worker-b"
      }
    },
    {
      "id": "h1",
      "type": "human_correction",
      "content": "Reviewer required the worker to add a failing regression test before changing production code."
    }
  ],
  "outcome": "corrected_by_human"
}
```

Save that JSON as `puppetmaster-job-42.json`, then run detection:

```bash
lessonweaver detect puppetmaster-job-42.json --save --registry-root /tmp/lw-puppetmaster
```

The failed finding and human correction are intentionally conservative signals.
This example emits multiple candidates, so follow-up commands choose a candidate
explicitly. Reviewers decide whether each lesson should become a skill, workflow
recommendation, guardrail, eval, or documentation update.

## Review gate

Use `review-trace` to keep ingestion, review answers, and optional approval in a
single audited command. This example turns the failed worker finding into
durable skill guidance:

```bash
lessonweaver review-trace puppetmaster-job-42.json \
  --registry-root /tmp/lw-puppetmaster \
  --candidate puppetmaster-job-42-failed-eval \
  --answer scope=project \
  --answer action_type=skill \
  --answer risk_level=high \
  --answer approval_requirement=explicit_approval \
  --answer applicability=high_risk \
  --answer negative_conditions=different_domain \
  --answer decision=approve \
  --approve \
  --approved-by reviewer
```

For a process-level change instead, choose `action_type=workflow_change` and
answer the workflow follow-up:

```bash
lessonweaver review-trace puppetmaster-job-42.json \
  --registry-root /tmp/lw-puppetmaster \
  --candidate puppetmaster-job-42-workflow-step-failure \
  --answer scope=project \
  --answer action_type=workflow_change \
  --answer workflow_determinism=deterministic_rule \
  --answer risk_level=high \
  --answer approval_requirement=explicit_approval \
  --answer applicability=high_risk \
  --answer negative_conditions=different_domain \
  --answer decision=approve
```

## Export targets

After review, choose the export target that matches how the orchestrator will
consume guidance:

```bash
# Project instructions for future coding workers
lessonweaver export-skill skill-puppetmaster-job-42-failed-eval \
  --format agents-md \
  --redact \
  --registry-root /tmp/lw-puppetmaster

# Runtime snippet for an orchestrator prompt or prompt store
lessonweaver export-skill skill-puppetmaster-job-42-failed-eval \
  --format runtime \
  --redact \
  --registry-root /tmp/lw-puppetmaster

# Workflow recommendation for a deterministic orchestration rule
lessonweaver export-lesson puppetmaster-job-42-workflow-step-failure \
  --format workflow \
  --redact \
  --registry-root /tmp/lw-puppetmaster
```

Only load or commit reviewed output. Do not let Puppetmaster workers activate
their own findings as rules without a human review gate.

## Non-goals

- No automatic self-training from worker findings.
- No unreviewed rule activation.
- No runtime dependency on Puppetmaster.
- No requirement that Puppetmaster adopt lessonweaver's internal registry.
